Temperature and PM2.5 forecasts for all 34 provinces of Vietnam, updated every hour

The system collects new data every hour and processes almost 2.8 million rows of history with PySpark. Our own XGBoost models forecast the next 1, 3 and 6 hours, and an AI assistant answers questions using the same data.

From the API to a forecast on the web

Each step is a separate Python script. Steps 1 and 4 run automatically every hour, on GitHub Actions and on our PC. The other steps run only when we retrain the models.

  1. Collect

    Call the Open-Meteo API for 34 locations (12 weather and 7 air quality variables), and scrape weather and disaster news from 8 Vietnamese news feeds.

    Every hourhistory since Nov 2021

  2. Process with PySpark

    Clean the data, remove duplicates and invalid values, join weather with air quality, and aggregate by province and month.

    25 seconds1,494,096 + 1,275,408 rows, 16 threads

  3. Train models

    6 XGBoost models on the GPU: temperature and PM2.5, each for 1, 3 and 6 hours ahead. The data is split by time.

    126 seconds47 and 75 features

  4. Forecast in real time

    Take the last 48 hours, build the same features as in training, and save forecasts for all 34 provinces.

    204 forecastsevery run

  5. Web app and AI assistant

    Streamlit shows the map, history, forecasts, news and evaluation. The assistant answers questions from our data and cites news sources.

    7 pagesrefresh every 5 minutes

Our model beats every baseline

We tested on the last 180 days, which the models never saw in training: 146,914 samples for each model. Lower mean absolute error (MAE) is better.

Ask a question, get an answer from real data

The assistant finds the province in your question, even with old province names from before the 2025 merger. It answers only with our data: current values, our model's forecasts, and news articles from our scraper, which it cites as [1], [2].

  • Two versions. On our PC, Qwen3 8B runs on our own RTX 4060 Ti GPU with Ollama. The online demo uses the Groq API, so the question and the selected data are sent to Groq.
  • Knows old names. Bình Dương and Vũng Tàu are now part of Ho Chi Minh City. Quy Nhơn is now in Gia Lai.
  • Shows its sources. News is cited with links, and every answer shows the exact data given to the AI.

Example only, not real data
Is it a good idea to go running in Bình Dương this afternoon?
Bình Dương is now part of Ho Chi Minh City. At 15:00 it is about 33 °C and the US AQI is moderate. Our model expects about 30 °C in 3 hours, so it is better to run after 17:30 and bring water.
How about Da Lat?
Da Lat (Lâm Đồng) is much cooler, about 20 °C, and the air quality is good. It is a more comfortable place to run.

Known limitations

  • The data comes from models, not weather stations

    The weather history is reanalysis data. PM2.5 comes from the CAMS model at about 45 km resolution, with one value every 3 hours. This data is smoother than real sensor data, so it is easier to forecast.

  • Training data and live data are different

    We train on reanalysis data but run on Open-Meteo's current data. We track the real accuracy separately on the Evaluation page.

  • Short-term forecasts only

    Forecasting 1 to 6 hours ahead is the easiest part of weather forecasting. Forecasts for several days need physical models and much more data.

  • One machine only

    Spark runs in local mode on one PC. We load the data into Spark with Apache Arrow, because Hadoop on Windows cannot read the files directly.
